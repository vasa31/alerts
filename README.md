# Мониторинг складов и пожарных датчиков

Простой backend на **FastAPI + SQLite + JWT** и кнопочный UI.  
Склады и датчики заданы при старте (два склада, по 3 датчика). Добавлять их через API/UI нельзя.

## Как запустить

```bash
cd /Users/roman/surkova
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Открыть:

- UI: http://127.0.0.1:8000/ui/  ← открывайте этот адрес, не файл `index.html`
- Swagger: http://127.0.0.1:8000/docs

Проверка:

```bash
./test_api.sh
```

Пароли в демо хранятся как есть.

## JWT

```bash
curl -s -X POST http://127.0.0.1:8000/api/login \
  -H "Content-Type: application/json" \
  -d '{"username":"duty","password":"duty"}'
```

Дальше: `Authorization: Bearer <access_token>`. Токен 12 часов.  
Показания датчиков (`/api/ingest/{ip}`) **без JWT**.

## Карта

Карта 500×400, координаты складов и датчиков приходят с бэка.

- **Склад А** (слева): датчики 1.1-T / 1.1-O2 / 1.1-S
- **Склад Б** (справа): датчики 2.1-T / 2.1-O2 / 2.1-S

Цвета:

- зелёный — ок
- серый — не работает (`offline`)
- красный мигает — тревога (`alarm`)

## Логика пожара (2 из 3)

На зоне всегда 3 датчика: температура, кислород, дым.

| Сколько мигает | Что происходит |
|----------------|----------------|
| **1 из 3** | Ложное. Уведомление дежурному, звук `soft`. В пожарную не шлём. |
| **2 из 3** | Подозрение. Стартует **окно наблюдения**. Датчики мигают, дежурный видит таймер. В пожарную ещё не шлём. |
| **3 из 3** | Сразу **пожар**. Звук `sharp`, вызов в пожарную. |

Окно при 2 из 3:

1. Засекаем время (`CONFIRM_SECONDS` в `app/logic.py`).
2. Если за окно датчики **затихли** (осталось 0 или 1) → **пожара нет**.
3. Если **всё ещё мигают 2+** после окна → **пожар**, уведомление в пожарную.
4. Если во время окна сработал **третий** → сразу пожар, ждать не нужно.

В демо окно **15 секунд**, чтобы проверить кнопками. На складе поставьте `CONFIRM_SECONDS = 300` (5 минут).

Зачем так: один датчик часто врёт (пыль, скачок). Два могут быть коротким всплеском. Три сразу или два, которые не гаснут — уже пожар.

Дежурный после выезда закрывает событие:

- `confirmed_fire` — пожар был
- `confirmed_false` — ложное

Статистика: `/api/stats`.

## Протокол датчика

Датчик шлёт HTTP POST со своего IP:

```json
{ "value": 72.5, "online": true }
```

| Поле | Смысл |
|------|--------|
| `value` | °C / O₂ % / дым |
| `online` | `false` → серый на карте |

Пороги склада А:

| Тип | IP | Тревога |
|-----|-----|---------|
| temperature | 192.168.1.11 | value > 60 |
| oxygen | 192.168.1.12 | value < 18 |
| smoke | 192.168.1.13 | value > 50 |

Склад Б: `192.168.1.21` / `.22` / `.23`, те же пороги.

```bash
curl -X POST http://127.0.0.1:8000/api/ingest/192.168.1.11 \
  -H "Content-Type: application/json" \
  -d '{"value": 90, "online": true}'
```

## Как проверить в UI

1. Войти как **duty**.
2. **1 тревога** → ложное, мигает один датчик.
3. **2 тревоги → наблюдение** → два красных, таймер на карте.
   - **Норма** до конца окна → пожара нет.
   - Подождать 15 сек **или** «Окно прошло» → пожар + уведомление пожарной.
4. **3 тревоги** → сразу пожар.
5. Дежурный: **Подтвердить ПОЖАР** или **Отметить ЛОЖНОЕ**.

## API

| Метод | Путь | Кто | Описание |
|-------|------|-----|----------|
| POST | `/api/login` | все | логин → JWT |
| GET | `/api/me` | JWT | кто вошёл |
| GET | `/api/map` | JWT | карта + зоны + таймер наблюдения |
| GET | `/api/sensors` | JWT | список датчиков |
| POST | `/api/ingest/{ip}` | датчик | показание |
| GET | `/api/notifications` | JWT | уведомления |
| GET | `/api/events` | JWT | события |
| POST | `/api/events/{id}/resolve` | duty/admin | пожар / ложное |
| POST | `/api/watch/check?force=true` | JWT | пересчёт окна (`force` — как будто время вышло) |
| GET | `/api/stats` | JWT | статистика |
