# Протокол взаимодействия программы и датчиков

## Что из себя представляют датчики

На каждой **зоне** склада стоят **3 датчика**:

| Тип | Поле | Когда тревога | Норма (кнопка «Сброс датчиков») |
|-----|------|----------------|----------------------------------|
| `temperature` | температура, °C | значение **>** порога (по умолчанию 60) | 24 |
| `oxygen` | уровень кислорода, % | значение **<** порога (по умолчанию 18) | 20.9 |
| `smoke` | задымление, усл. ед. | значение **>** порога (по умолчанию 50) | 5 |

У каждого датчика есть **IP**. Датчик сам периодически шлёт показания на сервер по HTTP.  
Склад А: `192.168.1.11` / `.12` / `.13`. Склад Б: `192.168.1.21` / `.22` / `.23`.

Сервер доступен через Docker: `http://127.0.0.1:8080`.

## Как выглядит обмен

```
Датчик (IP 192.168.1.11)
    │
    │  POST /api/ingest/192.168.1.11
    │  {"value": 72.5, "online": true}
    ▼
FastAPI (сервис api)
    │  обновляет статус датчика (ok / alarm / offline)
    │  пересчитывает зону (правило 1/2/3)
    │  пишет событие в SQLite
    ▼
Дежурный (карта + уведомления)
    │  при пожаре — копия в пожарную (target=fire_dept)
    │  та же строка события уходит в Telegram
    ▼
Бот (сервис bot) → чаты с /start
    ▼
Подтверждение дежурного: confirmed_fire | confirmed_false
```

Ползунки на пульте вызывают тот же `POST /api/ingest/{ip}`. JWT для показаний не нужен.

## Пример данных от датчика

Норма:

```json
{"value": 24.0, "online": true}
```

Пожар по температуре:

```json
{"value": 85.0, "online": true}
```

Мало кислорода:

```json
{"value": 15.2, "online": true}
```

Сильное задымление:

```json
{"value": 90.0, "online": true}
```

Датчик вышел из строя / нет связи:

```json
{"value": 0, "online": false}
```

Ответ сервера (пример):

```json
{
  "id": 1,
  "zone_id": 1,
  "sensor_type": "temperature",
  "name": "Датчик 1.1-T",
  "ip": "192.168.1.11",
  "status": "alarm",
  "last_value": 85.0,
  "map_color": "red",
  "threshold": 60.0
}
```

## Цвета на карте

- **green** — `ok`, датчик работает
- **gray** — `offline`, вышел из строя
- **red** — `alarm`, активная тревога (на UI мигает)

## Логика 1 / 2 / 3

На точке всегда 3 датчика.

| Сколько в `alarm` | Что происходит |
|-------------------|----------------|
| **1 из 3** | Ложное срабатывание. Звук `soft`, только дежурному. В пожарную и в Telegram не шлём. |
| **2 из 3** | Окно наблюдения (`CONFIRM_SECONDS`, в демо 15 секунд). В пожарную пока не шлём. |
| **3 из 3** | Сразу пожар. Звук `sharp`, уведомление `fire_dept` и сообщение в Telegram. |

Окно наблюдения:

1. Засекается время.
2. Если за окно осталось 0 или 1 датчик в тревоге — пожара нет.
3. Если после окна всё ещё 2 или больше — пожар, вызов пожарной и Telegram.
4. Если во время окна сработал третий датчик — пожар сразу.

Один датчик `offline` при работающих остальных — уведомление «проверьте датчик», это не пожар.

Дежурный после выезда отмечает `confirmed_fire` или `confirmed_false`. В `/api/stats` видна доля ложных срабатываний.

Кнопка **Сброс датчиков** (`POST /api/sensors/reset`, нужен JWT) возвращает все показания в норму и закрывает открытые события. Это сброс имитации, не подтверждение выезда.

## Telegram

Бот читает ту же базу, что и API. В Telegram уходит только новое событие `fire_signal`, пока у него `telegram_sent = false`. После успешной отправки флаг становится `true`.

Подписка: написать боту `/start`. Отписка: `/stop`. Получатели хранятся в таблице `telegram_chats`.

## Роли

| Пользователь | Пароль | Роль |
|--------------|--------|------|
| `duty` | `duty` | пульт: карта, ползунки, сброс, подтверждение событий |
| `admin` | `admin` | кабинет: карта, статистика, вызовы пожарной |

Склады и датчики через интерфейс не добавляются. Вход — `POST /api/login`, дальше заголовок `Authorization: Bearer <token>`.
