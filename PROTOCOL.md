# Протокол взаимодействия программы и датчиков

## Что из себя представляют датчики

На каждой **зоне** склада стоят **3 датчика**:

| Тип | Поле | Когда тревога |
|-----|------|---------------|
| `temperature` | температура, °C | значение **>** порога (по умолчанию 60) |
| `oxygen` | уровень кислорода, % | значение **<** порога (по умолчанию 18) |
| `smoke` | задымление, усл. ед. | значение **>** порога (по умолчанию 50) |

У каждого датчика есть **IP** (например `192.168.1.11`). Датчик сам периодически шлёт показания на сервер по HTTP.

## Как выглядит обмен

```
Датчик (IP 192.168.1.11)
    │
    │  POST /api/ingest/192.168.1.11
    │  {"value": 72.5, "online": true}
    ▼
FastAPI сервер
    │  обновляет статус датчика (ok / alarm / offline)
    │  пересчитывает зону (правило 1/2/3)
    ▼
Дежурный (карта + уведомления)
    │  при пожаре — копия в пожарную (target=fire_dept)
    ▼
Подтверждение: confirmed_fire | confirmed_false
```

## Пример данных от датчика

Норма:

```json
{"value": 24.0, "online": true}
```

Пожар по температуре:

```json
{"value": 85.0, "online": true}
```

Мало кислорода:

```json
{"value": 15.2, "online": true}
```

Сильное задымление:

```json
{"value": 90.0, "online": true}
```

Датчик вышел из строя / нет связи:

```json
{"value": 0, "online": false}
```

Ответ сервера (пример):

```json
{
  "id": 1,
  "zone_id": 1,
  "sensor_type": "temperature",
  "name": "Датчик 1.1-T",
  "ip": "192.168.1.11",
  "status": "alarm",
  "last_value": 85.0,
  "map_color": "red",
  "threshold": 60.0
}
```

## Цвета на карте

- **green** — `ok`, датчик работает
- **gray** — `offline`, вышел из строя
- **red** — `alarm`, активная тревога (на UI мигает)

## Логика «лучше старого протокола»

Раньше был 1 датчик → любое срабатывание = тревога (много ложных).

Теперь на точке 3 датчика:

- **2 или 3** в `alarm` → сигнал **пожар** (звук `sharp`, уходит в пожарную)
- **ровно 1** в `alarm` → сигнал **ложное** (звук `soft`, только дежурному)
- **2 из 3 работают**, 1 `offline` → уведомление «проверьте датчик»

Дежурный после выезда отмечает `confirmed_fire` или `confirmed_false` → в `/api/stats` видно долю ложных срабатываний.

## Роли

| Пользователь | Пароль | Роль |
|--------------|--------|------|
| admin | admin | добавляет склады, зоны, датчики |
| duty | duty | карта, уведомления, подтверждение событий |

Авторизация простая: заголовок `X-User: admin` или `X-User: duty`.
